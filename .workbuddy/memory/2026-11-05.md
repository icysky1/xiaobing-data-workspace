## 推演引擎与静态口径不一致导致胜率反向（用户报告：静态占优但推演胜率 0%）
- 矩阵测试（A/B/C 三套阵容互打 6 组）暴露：AvC 静态 A 优 +976，推演胜率却 0%（完全反向）；growth=0 也反向 → 不是成长参数问题。
- 根因 3 个（都在 buildBattleSide）：
  1) 符号 bug：Math.abs(a.v) 把「双方全体男性-20%」这类 both 减益作用到自己人时变成 +20%；
  2) 静态 applyEffect 用加算（kf=1+Σv 带符号），推演把 p=1 确定效果也做成 proc 且 mul 连乘 → 期望脱钩、指数膨胀；
  3) 推演 power 用纯基础值，静态的确定加成（羁绊/阵营/军师技/非概率技能）根本没进推演，且静态 ×2 口径推演没乘。
- 修复（lineup.js buildBattleSide/buildBattleSides 重构为两阶段）：
  阶段一：prob=1 确定效果按静态公式 (base+df)×(1+Σv) 直接折进单位 power（自身 own/both + 对方 enemy/both 减益），×FINAL_MULT 对齐口径；
  阶段二 attachBattleProcs：p<1 概率效果作为 proc roll（带符号 v，p×scale 合并），battleSim DEFAULTS.stacking 改 add（期望=静态 Σp·v）、growth 默认 0。
- 结果：6 组矩阵方向 6/6 与静态一致；校准 K=0.045、14~22 回合最优（B1/B2 命中，B3 极端雪球局本来就无法无雪球模型复现）。
- 推演战力=「战斗结束时存活单位」快照，天然低于开战底力，页面 note 文案已更新说明；重点看胜率与相对高低。
- 生成算法本身没问题的确认：优化器目标=静态净胜差，静态已含阵营克制/羁绊/技能期望/军师技；之前的问题是推演侧口径错误，让用户误以为生成不可信。

## 推演胜率 0% vs 静态占优（第二次修复：彻底重构口径，用户报告 + 截图）
- 症状：生成阵容静态 10777~11578 vs 敌 8733~9409（占优），推演却 0% 胜率、平均 82.8% 平局。
- 根因（3 层）：
  1) battleSim 旧模型是「逐排捉对决斗」：每排满血输出到整排打空，战斗普遍打不满 14~22 回合，几乎全靠回合上限+剩余血量判胜负 → 结果与总战力脱钩，出现大面积平局和方向反转；
  2) attachBattleProcs 的 pushProc 用 target.units.indexOf(pool 单位) 找下标，但两者是不同对象数组 → 概率技能 proc 从来都是空的（从未 roll 过）；
  3) buildBattleSide 用「只含确定性效果」的 det 口径近似静态，遗漏了 buffAmp/免疫/沉默/钉选等元修正，与静态总战力差 ~10%。
- 修复（battleSim.js + lineup.js）：
  1) 新伤害模型：单位血量=战力×倍率；每回合双方同时输出 K×我方有效血量（有效血量=Σ各排 血量×剩余百分比），绝对伤害按 前排→中排→后排 逐排扣，扣空整排灭；打满回合按剩余血量比例判胜。战力高的一方每回合损耗更慢 → 静态占优 ↔ 推演胜率高（构造性保证）；
  2) 推演起算战力直接取静态 computeSide 全量结果（buildBattleSide(label, res) 读 effFmin/effFmax 中值×FINAL_MULT），与页面战力对比同一份数据、同一个公式——验证：静态 8032 vs 推演起算 8031（取整差 1）；删除 detOnly/isProbEff/procDvOf/attachBattleProcs/unitPowerOf 等全部近似代码；
  3) 快照口径：存活单位全额战力（阵亡整排消失，残排不按百分比折算）→ 推演战力与静态同量级可直接对照。
- 验证：A/B/C 三套阵容 6 组互打全部方向一致且镜像对称（A vs B 100% / B vs A 0% 等）；test-pet-default / test-battle-ui / test-gen-allpets 回归通过。
- 注意：胜负判定仍可能有小幅波动（回合数 14~22 随机），接近的对抗会出现平局；快照战力可能在「双方都掉了前排」时与静态排序不同（前排大小不同），以胜率为准。
- 同时按用户要求删除 3 处说明文字：生成算法说明（wxml）、阵容码口径说明（wxml）、推演口径 note（js + wxml）。

## 推演改为「号位 1→18 交替释放技能 → 只拼数据」（用户给出三条规则）
- 规则（用户确认）：① 开场按号位 1→18：先手方 1 号位放全部技能 → 后手方 1 号位 → 2 号位 … → 18 号位，各放一次；② 先手方 = 发起挑战方（本工具＝我方）；③ 号位只放技能（buff/减益/控制），不造成伤害，放完只比数据。
- battleSim.js 全重写：删除逐回合掉血模型。新流程 = 被动（阵营/羁绊/阵容技/军师技）→ 号位 1..18 交替出手（先手方先）→ 终局战力比大小（±2% 战斗浮动，否则同分全平）。被控（技能无效）且尚未出手的单位整场技能作废。
- 输入 side = { units[{name,row,slot,baseFmin/Fmax,Imin/Imax}], skills[{from,slot,kind:'buff'|'silence'|'pin',p,own[{t,pf,pi,df,di}],foe[...],hits[...]}] }。
- lineup.js：computeSide 新增 opt.trace（逐效果记录增量，直接取自静态那一次结算，公式同源）；buildBattleSides 用 traceO/traceE 组装技能包；sidePackets 按 holder 的号位分组。删掉 deltaOf/scratchUnits 那套影子单位近似。
- 口径校验（全员必放 p=1）：A vs C 我方 6474 vs 静态 6447；C vs B 双方 8540/9201 vs 静态 8540/9202；2000 场均 8540/9205（偏差 <0.1%）。
- 顺带修 bug：resetUnits 没清 buffAmp / negTaken，军师技重算第二遍会重复放大（增益放大被叠两次），静态总战力偏高（例：8032→7620 变化）。
- 关键发现 1：先手只在「同号位相遇」时决定谁先放（because 号位号 → 出手次序），实测约值 1.5pp。
- 关键发现 2：真正的杠杆是「谁排低号位」——同排内只轮换位置（静态战力完全不变 8032），A vs B 胜率在 65.2%~83.3% 之间波动，极差 18pp。生成器目前按贪心填格，不看号位顺序 → 有 10~15pp 的「站位浪费」，待做号位择优。
- 面板：显示终局战力（≈静态）、先手方、平均压掉对方几人；删除「平均回合」。
